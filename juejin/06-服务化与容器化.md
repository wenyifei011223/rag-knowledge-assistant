## 一、最小可用服务只需要两个接口

`/ask` 接收问题返回结果，`/health` 给探活用。再加一个 `/docs` 说明接口契约，够用了。

这里有个现实问题：本环境没装 FastAPI。是停下来装依赖，还是先把服务跑通？我选了后者——用 Python 标准库 `http.server` 实现同样的接口，先证明"服务封装"这件事成立。

```python
class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if path == "/health":
            self._send(200, {"status": "ok"})
        elif path == "/docs":
            self._send(200, {"endpoints": [...]})   # 接口契约

    def do_POST(self):
        data = json.loads(self.rfile.read(length))
        question = data.get("question", "")
        if not question.strip():                     # 校验先行
            self._send(422, {"error": "question 必填且不能为空"}); return
        result = react_agent.run(question)
        self._send(200, {"answer": result["final_answer"],
                         "message_count": len(result["message_chain"]),
                         "memory": MEM.get_context(thread_id)})
```

接口契约和 FastAPI 版完全一致——装好依赖后 `main.py` 直接顶上，调用方不用改。

## 二、一个容易被忽略的细节：422 而不是 500

空问题进来，如果直接让下游处理，大概率抛异常返回 500。这是接口工程的基本功：请求校验失败应该返回 422（语义错误），不是 500（服务崩了）。

```python
if not isinstance(question, str) or not question.strip():
    self._send(422, {"error": "question 必填且不能为空"})
```

FastAPI 版用 Pydantic 模型做同样的事，而且能自动生成 OpenAPI 文档：

```python
class Query(BaseModel):
    question: str = Field(description="用户问题，不能为空")
    thread_id: str = "default"

@app.post("/ask")
def ask(q: Query): ...
```

## 三、会话记忆与上下文压缩

`thread_id` 决定记忆归属：同一个 id 的多次请求共享上下文。但历史会无限膨胀，所以要压缩。

我的实现是：当历史条数超过阈值，把早期消息压成一段累积摘要，只保留最近几条原文。

```python
def _compress(self, thread_id, history):
    early = history[:-2]                  # 早期消息
    digest = " | ".join(f"{m['role']}:{m['content'][:40]}" for m in early)
    prev = self.summaries.get(thread_id, "")
    self.summaries[thread_id] = (f"{prev} | {digest}" if prev else digest)[-500:]
    self.store[thread_id] = history[-2:]  # 保留最近 2 条
```

这里我踩过一个坑：第一版每次压缩都覆盖摘要，结果只剩最后一轮的内容，早期上下文全丢了。改成**累积**才对——摘要要拼接上次的，而不是替换。

实测 6 轮对话后：早期 4 轮压成摘要（`user:问题0 | assistant:回答0 | ...`），最近 4 条保留原文。

## 四、Docker：写好但不硬吹

Dockerfile 分层写，利用构建缓存——先复制依赖清单安装，最后复制代码：

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

代码改动只触发最后一层 COPY，依赖不重装。Key 通过 `--env-file .env` 传，不进镜像。

但**本环境没有 Docker，我没构建验证**。所以本文不贴 `docker ps` 截图，简历也只写"了解 Docker 容器化部署"。没验证的东西写"完成"，面试一问就穿。

## 五、真实 curl 结果

服务跑在 8765 端口，四个请求的实际返回：

```
GET  /health  -> {"status": "ok"}
GET  /docs    -> {"title":"ReAct 多智能体问答服务", "endpoints":[...]}
POST /ask     -> {"answer":"根据检索到的证据回答：... [来源: ...]",
                  "message_count": 4, "memory": {...}}
POST /ask {"question":""} -> {"error": "question 必填且不能为空"}
```

`message_count=4` 正好对应 ReAct 的完整 4 条消息链——服务层和 Agent 层是对齐的。
