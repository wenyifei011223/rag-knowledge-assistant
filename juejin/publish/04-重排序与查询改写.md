召回解决了"找得到"，但 Top-k 里仍有无关项；多轮对话里"它为什么这么做"这种追问，直接检索几乎召不回东西。这两件事不解决，前面的混合检索做得再好也白搭。

这篇讲两阶段检索里的重排（rerank）和多轮对话的查询改写（query rewrite），以及一个我真实踩过并修掉的坑。

## 一、重排：只作用在候选集上

```python
def rerank(query, results, store):
    try:
        model = CrossEncoder("BAAI/bge-reranker-base")
        scores = model.predict([[query, r["text"]] for r in results])
        ...                                   # cross-encoder 联合编码
    except Exception:
        coverage = len(set(tokenize(query)) & set(tokenize(r["text"]))) / len(qtokens)
        r["rerank_score"] = r.get("score", 0) * (1 + coverage)  # 词项覆盖降级
    return sorted(results, key=lambda x: x["rerank_score"], reverse=True)
```

关键点：**重排只在候选集上做**。cross-encoder 无法预计算文档向量，把全库拿去精排会慢到不可用。所以流程是先用向量/BM25 召回 `max(20, k*5)` 个候选，再精排取 Top-k。

## 二、查询改写：让追问能独立检索

```python
if llm:
    return llm.strip(), "deepseek-rewrite"          # 大模型改写
return " ".join(history[-2:] + [query]), "rule-based-rewrite-fallback"  # 规则兜底
```

有大模型 Key 用模型把追问改写成独立问题；没有就规则兜底，至少把历史里的领域词带进检索，避免追问召不回。

## 三、踩坑：域外判定要用改写后的问题

这是最值得说的一个坑。

多轮追问"它为什么这么做"本身没有任何领域词。如果域外判定拿**原句**去判，词项覆盖为零，会被当成域外问题直接拒答——一个合法的追问被误杀了。

修法：域外判定作用在**改写后**的问题上。改写把历史"为什么要使用混合检索"的领域词带了进来，判定就正常了。这个 bug 我实际调试过，修完用 `evidence/query_rewrite.json` 留了证据。

另外两个细节：

- 输出必须记录**实际用的重排方式**，否则会把降级数字当正式结果发出去。
- 改写失败不能中断链路，规则降级要保底。

## 四、结果验证

- `evidence/query_rewrite.json`：追问"它为什么这么做" + 历史"为什么要使用混合检索"，改写类型 `rule-based-rewrite-fallback`，返回领域内回答 ✓
- `evidence/retrieve_compare.txt`：rerank 模式与 hybrid 模式同一问题的对比输出

**必须标注的局限**：当前环境未装 CrossEncoder，重排走的是词项覆盖降级方案（`lexical-coverage-fallback`），不是真正的 bge-reranker 精排。装好后需要重跑，用正式数据替换降级结果。

## 结语

召回、重排、改写是三件不同的事：召回管"全不全"，重排管"准不准"，改写管"追问能不能独立检索"。把职责拆清楚，每一环都能单独调、单独测，出了问题也好定位。
