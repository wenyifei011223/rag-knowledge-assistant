稠密向量懂语义但对精确代号不稳定，BM25 抓精确词项但没有语义。把两路检索融合，能不能兼顾"意思相近"和"字面精确"？这篇用实验说话——包括一个不太好看但必须说的结果。

## 一、四种检索方式

`retrieve.py` 提供四种模式：`vector`（纯向量）/ `bm25` / `hybrid`（融合）/ `rerank`（融合+重排）。

- 向量：本地 TF-IDF 稠密向量（可切 bge）
- 稀疏：BM25（K1=1.5, B=0.75）
- 融合：RRF，常数 k=60

## 二、核心实现：RRF 按名次融合

```python
def rrf_fuse(dense, bm25, top_k):
    fused = {}
    for rank, item in enumerate(dense, 1):
        fused.setdefault(item["id"], {**item, "score": 0.0})["score"] += 1 / (60 + rank)
    for rank, item in enumerate(bm25, 1):
        fused.setdefault(item["id"], {**item, "score": 0.0})["score"] += 1 / (60 + rank)
    return sorted(fused.values(), key=lambda x: x["score"], reverse=True)[:top_k]
```

RRF 的关键：**只用名次，不用原始分数**。所以两路分数不需要归一化，某一路的异常高分也不会主导结果。这是它比加权求和省事的地方。

## 三、踩坑：分词必须一致，权重不能照抄

- 中文分词用单字 + 字母数字 token，**入库和检索必须用同一套分词**，否则大小写/单字对不上。
- BM25 长文档要做长度归一化，否则长文天然占优。
- 权重不是照抄默认值 0.4/0.6，要在自己的评测集上扫。

## 四、结果：J-N 组真实数据

固定 `chunk500 / overlap100 / k4`：

| 组 | 方式 | 命中率 | 平均延迟 |
|---|---|---:|---:|
| J | 纯向量 | 96.67% | 0.0024s |
| K | 混合 [0.4,0.6] | 100.00% | 0.0051s |
| **L** | **混合+重排（基线）** | **100.00%** | 0.0078s |
| M | 混合 [0.6,0.4] | 100.00% | 0.0051s |
| N | 混合 [0.3,0.7] | 100.00% | 0.0052s |

## 五、诚实结论：三组权重全部打平

纯向量延迟最低（0.0024s）但少命中一题；三种混合权重全部 100%，**没有差异**。

为什么不硬编一个"最优权重"出来？因为当前评测集缺少精确标识符类的题，BM25 的特长根本没被考到——三组权重打平恰恰说明这个数据集测不出权重的差别。正确的做法是补上"编号、代号、专有名词"这类题再定权重，而不是在打平的数据里挑一个写成结论。

> 这也是我想强调的：实验结果不好看、不显著，如实写出来比硬凑一个结论更可信。

## 六、局限

示例语料只有 5 篇，向量是 TF-IDF 降级实现，不是 bge；这些数字用来展示方法，不能外推到真实业务。换 bge + 真实语料后需要重跑。

## 结语

混合检索的价值在"语义召回 + 词项召回互补"，RRF 让融合不必归一化分数。但要验证它值不值，你的评测集必须同时包含语义题和精确标识符题，否则就是拿一把只有刻度的尺子量温度。
