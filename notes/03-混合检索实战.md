# 03 混合检索实战：BM25 + 向量检索 + RRF 融合

> 对应技能：检索与知识库 ｜ 状态：已跑对照实验 ｜ **推荐发掘金**

## 1. 背景与目标

稠密向量懂语义但对精确代号不稳定，BM25 抓精确词项但没有语义。目标是把两路检索融合，兼顾"意思相近"和"字面精确"，并用实验验证混合到底值不值。

## 2. 环境与依赖

- `retrieve.py`：四种模式 vector / bm25 / hybrid / rerank
- 向量：本地 TF-IDF 稠密向量（可切 bge）；稀疏：BM25（K1=1.5, B=0.75）
- 融合：RRF，常数 k=60

## 3. 核心实现

```python
def rrf_fuse(dense, bm25, top_k):
    fused = {}
    for rank, item in enumerate(dense, 1):
        fused.setdefault(item["id"], {**item, "score": 0.0})["score"] += 1 / (60 + rank)
    for rank, item in enumerate(bm25, 1):
        fused.setdefault(item["id"], {**item, "score": 0.0})["score"] += 1 / (60 + rank)
    return sorted(fused.values(), key=lambda x: x["score"], reverse=True)[:top_k]
```

RRF 的关键：只用名次、不用原始分数，因此两路分数不需要归一化，某一路的异常高分也不会主导结果。

## 4. 关键参数与踩坑

- 中文分词用单字+字母数字 token，入库和检索必须用**同一套分词**，否则大小写/单字对不上。
- BM25 长文档要长度归一化，否则长文天然占优。
- 权重不是照抄默认值，要在自己的评测集上扫（见结果）。

## 5. 结果验证

J-N 组（固定 chunk500/overlap100/k4）：

| 组 | 方式 | 命中率 | 平均延迟 |
|---|---|---:|---:|
| J | 纯向量 | 96.67% | 0.0024s |
| K | 混合 [0.4,0.6] | 100.00% | 0.0051s |
| **L** | **混合+重排（基线）** | **100.00%** | 0.0078s |
| M | 混合 [0.6,0.4] | 100.00% | 0.0051s |
| N | 混合 [0.3,0.7] | 100.00% | 0.0052s |

四种模式同一问题的原始输出见 `evidence/retrieve_compare.txt`。

**诚实结论**：纯向量延迟最低但少命中一题；三种混合权重全部打平，说明当前评测集缺少精确标识符题，BM25 的特长没被考到——这点必须在文章里写出来，不能硬编差异。

## 6. 面试怎么讲

"混合检索是语义召回和词项召回互补。稠密向量把查询和文档映射到同一空间，BM25 靠词频和逆文档率抓精确代号。我用 RRF 按名次融合，不需要归一化分数。实验上混合比纯向量多命中一题，但延迟从 0.0024 涨到 0.005；权重扫描三组打平，因为评测集标识符题不够，我会如实说明需要补题再定权重。"
