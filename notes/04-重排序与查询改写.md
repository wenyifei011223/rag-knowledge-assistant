# 04 重排序与查询改写：让召回质量再上一个台阶

> 对应技能：检索与知识库 ｜ 状态：已实现并跑通（重排为降级方案）

## 1. 背景与目标

召回解决了"找得到"，但 Top-k 里仍有无关项；多轮对话里"它为什么这么做"这种追问直接检索几乎召不回东西。目标是用重排提升精度、用查询改写让追问可独立检索。

## 2. 环境与依赖

- `retrieve.py` 的 `rerank()`：检测到 CrossEncoder 用 `bge-reranker-base`，否则用词项覆盖降级
- `rag_chain.py` 的 `rewrite_query()`：有 Key 用 DeepSeek 改写，否则规则降级
- 证据：`evidence/query_rewrite.json`、`evidence/rag_answer_in_domain.json`

## 3. 核心实现

重排（两阶段）：

```python
def rerank(query, results, store):
    try:
        model = CrossEncoder("BAAI/bge-reranker-base")
        scores = model.predict([[query, r["text"]] for r in results])
        ...                                   # cross-encoder 联合编码
    except Exception:
        coverage = len(set(tokenize(query)) & set(tokenize(r["text"]))) / len(qtokens)
        r["rerank_score"] = r.get("score", 0) * (1 + coverage)  # 词项覆盖降级
    return sorted(results, key=lambda x: x["rerank_score"], reverse=True)
```

关键：重排**只在候选集上做**。cross-encoder 无法预计算文档向量，全库精排会慢到不可用。

查询改写：

if llm:

## 4. 关键参数与踩坑

- 召回池取 `max(20, k*5)`，先多召回再精排。
- 输出必须记录实际用的重排方式，否则会把降级数字当正式结果。
- **域外判定要用改写后的问题**，直接拿"它为什么这么做"判会误拒（这个坑我踩过并修了）。
- 改写失败不能中断链路，规则降级至少把领域词带进检索。

## 5. 结果验证

- `evidence/query_rewrite.json`：追问"它为什么这么做"+历史"为什么要使用混合检索"，改写类型 `rule-based-rewrite-fallback`，返回领域内回答 ✓
- `evidence/retrieve_compare.txt`：rerank 模式与 hybrid 模式对比输出
- 当前环境未装 CrossEncoder，重排走的是词项覆盖降级——**这条必须标注**

## 6. 面试怎么讲

"重排是两阶段检索：先向量和 BM25 召回几十个候选，再用 cross-encoder 联合编码精排。cross-encoder 比双塔准但慢、不能预计算，所以只用在候选集。查询改写把追问和历史合并成独立问题，有大模型用模型改，没有就规则兜底。有个坑是域外判定要用改写后的问题，不然代词追问会被误拒。当前环境没装 CrossEncoder，走的是词项覆盖降级，正式结果要用真模型重跑。"

> 待补：装 CrossEncoder 后重跑，把降级结果替换成正式精排数据。
