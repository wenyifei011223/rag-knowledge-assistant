# RAG 实现链路：从原始文档到可核查回答

这条链路拆成离线和在线两段。离线段负责把文档变成可检索的索引，在线段负责把问题变成带引用的回答。拆开的好处是每一段都能单独评测、单独替换实现。

## ingest.py：加载、清洗、分块、入库

离线入库脚本负责四个步骤。第一步加载：遍历语料目录的 Markdown 文件，按 UTF-8 读取。第二步清洗：统一换行符、压缩连续空格和三个以上空行、去掉首尾空白，避免格式噪声进入向量。第三步分块：按固定字符数切片，配合重叠窗口，每块记录来源文件名和块内序号，形成形如 `01_rag_concepts.md#003` 的稳定 ID。第四步入库：为每块计算向量，连同原文、元数据一起写入本地 JSON 文件。

分块参数默认 chunk_size=500、overlap=100。这两个值是起点不是结论，必须通过在评测集上跑对照实验来选定。脚本支持命令行覆盖参数，便于批量实验时不必改代码。对照实验的基线固定为 chunk_size=500、overlap=100、k=4、混合检索加重排序，其余实验组相对这组基线逐个改变量。

向量化有两种实现。默认用本地 TF-IDF 稠密向量：对语料构建词表，用 tf-idf 加权后做 L2 归一化，零依赖、可复现，适合在没有网络和模型权重的环境里跑通全链路。检测到 sentence-transformers 已安装时自动切换到 bge-small-zh-v1.5，用真正的语义向量替换词项向量。切换后所有实验数字都要重跑，不能沿用旧数字。

入库产物要记录 embedding 类型、分块参数和全部块数据。这样后续检索脚本知道该用哪套向量计算方式，评测结果也能对应到具体的索引配置。

## retrieve.py：四种检索方式

检索脚本提供四种模式，方便在同一问题上手臂对比。

vector 模式只做稠密向量检索，按余弦相似度排序。它快，因为没有 BM25 打分和融合步骤，适合纯语义问题。

bm25 模式只做稀疏词项检索。它保留原文档的词项形态，对精确代号、参数名、错误码的查询最有效。

hybrid 模式做混合检索：两路各自召回候选池，再用 RRF 按排名融合。RRF 的妙处是不需要归一化两路的分数，只把名次换算成贡献值累加。融合后的结果兼顾语义和词项，但对顶部结果仍然偏保守。

rerank 模式在混合检索基础上加精排。它先取更大的候选池，用 cross-encoder 对查询-段落对打分；没有 cross-encoder 时用词项覆盖率降级。脚本会在输出里打印实际使用的重排方式，避免把降级结果误认为精排结果。

四种模式共用同一份索引和同一套分词逻辑，这一点很重要：如果检索和入库用了不同的分词规则，中文单字和英文大小写就会出现对不上的情况，命中率会莫名其妙地低。

## rag_chain.py：从检索结果到回答

在线链路按顺序做五件事。第一，查询改写：有历史对话时把追问改写成独立问题，并记录改写类型。第二，混合检索加精排：拿到带来源 ID 的候选段落。第三，域外判断：过滤通用疑问词后，检查查询的领域词项是否与召回内容有实质重合，相似度过低或无重合则直接拒答。第四，构造上下文：每段前面标注来源编号，拼成提示词的上下文部分。第五，生成回答：有 DeepSeek Key 时调用大模型按提示词生成；没有 Key 时用抽取式回答，只从原文挑出与查询词项重合度最高的句子，绝不自行组织不存在的结论。

提示词的核心约束只有三条：只用上下文、每个结论标注来源、没有依据就说"未找到相关依据"。这三条看似简单，却是把模型从"自由发挥"约束成"带证据的整理者"的关键。回答里出现的每个来源编号都应该能在上下文里找到，也能回到语料原文。

输出为 JSON，包含改写后的问题、改写类型、检索方式、引用块、回答文本、最大相似度和生成方式。把这些中间量留下来，是为了出问题时能定位是哪一环失效。

## eval_set.json：评测集怎么建

评测集每条记录包含题目 ID、问题文本、正确来源文件名和关键词。来源文件名用于计算命中率：Top-k 结果里出现标注的正确来源就算命中。关键词用于在抽取式回答里判断答案是否包含关键信息。

建评测集有三条原则。题目要覆盖不同问法：定义型、原因型、参数型、流程型都要有，不能全是同一种。正确答案的来源必须是可核查的现有文档，不能先编答案再找依据。域外题要单独标注，用来测拒答能力，不能混进命中率统计。

评测集要独立于实验参数。它标注的是"哪个文档回答这个问题"，而不是"哪次检索能找到它"，这样调 chunk_size、k、权重时才能公平比较。评测集一旦确定就不要为了让数字好看而改标注。

## 命中率不是唯一指标

命中率只回答"正确来源有没有进 Top-k"，不回答"拿进提示词后模型有没有用对"。完整的评测至少还要看三项：引用准确率（回答标注的来源是否真的支持该结论）、拒答准确率（域外问题是否正确拒答）、端到端延迟（从提问到出答案的耗时）。本项目的 14 组实验主要测命中率和延迟，其余指标需要在接入大模型后补齐。

在小语料上得到的数字要谨慎解读。5 篇文档、30 题的评测集能验证链路是否跑通、参数变化方向是否合理，但不足以宣称某个配置在通用场景最优。写结论时要带上语料规模前提。
