# RAG 还在胡编？两道防线把回答按在证据上

"只根据上下文回答，不要编造"——这句话几乎出现在每个 RAG 提示词模板里。但现实是：模型照样编。原因往往不在提示词写得不够狠，而在检索环节已经把一堆无关段落塞进了上下文。

模型看到上下文里有字，就觉得"有依据"。你给它一段讲混合检索的文字，用户问的是天气，它可能从里面挑一句"怎么保证回答不编造"来硬凑答案。这不是模型的错，是输入本身就诱导它编。

## 第一道防线：检索侧的域外判定

在组装提示词之前，先判断"召回内容到底有没有回答这个问题的材料"。

最简单的做法是用相似度阈值：相似度低于某个值就拒答。但我实测发现这招不稳。中文里"今天天气怎么样"和"怎么保证回答不编造"共享"怎么""怎么样"这类通用词，TF-IDF 余弦相似度并不低。阈值设高了误拒域内问题，设低了域外问题照样漏进来。

换成词项覆盖判定后稳定多了：

```python
GENERIC_BIGRAMS = {"怎么", "什么", "为什么", "怎么样", "如何", "今天", "我们", "可以", "这个", "那个", "一个", "没有"}

def domain_tokens(text):
    tokens = set(re.findall(r"[A-Za-z0-9]+", text.lower()))
    for run in re.findall(r"[\u4e00-\u9fff]{2,}", text):
        tokens.update(run[i:i + 2] for i in range(len(run) - 1))
    return {t for t in tokens if t not in GENERIC_BIGRAMS}

def domain_guard(query, results):
    qtokens = domain_tokens(query)
    corpus_tokens = set()
    for r in results:
        corpus_tokens.update(domain_tokens(r["text"]))
    return len(qtokens & corpus_tokens) >= 2 or any(len(t) >= 3 for t in (qtokens & corpus_tokens))
```

几个关键点：

- **中文按二元组切**，不按单字。"天气"是一个词，"天"和"气"分别是常见字，单字匹配会产生大量假阳性。
- **过滤通用二元组**。"怎么""什么""今天"这些词在任何中文问题里都出现，对判定没有贡献。
- **要求至少两个词项重合，或一个长度≥3 的词项命中**。一个"的"字重合不算证据。

实测结果：对"广州明天适合穿什么衣服""晚饭吃什么""下周股票会涨吗"这类完全无关的问题，都能稳定返回"未找到相关依据"。

## 第二道防线：提示词把引用写死

检索侧挡住了域外问题，域内问题还要保证每句话都能溯源。提示词三条约束：

```text
1. 只能使用【上下文】里的信息，禁止使用外部知识或猜测。
2. 每个结论后面必须标注来源编号，例如 [来源: 02_rag_pipeline.md#008]。
3. 如果上下文没有足够依据，必须固定回复：未找到相关依据。
4. 不要编造数字、日期、参数或文件名。
```

第 4 条容易被忽略，但对技术类知识库特别重要。模型很擅长"合理地补全"一个参数值，比如把 500 写成 512——看起来更专业，实际是编的。

上下文组装时给每段加编号：

```python
def build_context(results):
    parts = []
    for i, r in enumerate(results, 1):
        parts.append(f"[{i}] [来源: {r['id']}]\n{r['text']}")
    return "\n\n".join(parts)
```

来源 ID 用的是 `文件名#块号`，回答里的编号能直接定位回原文。这比"根据相关资料"这种模糊说法强得多——使用者可以自己核对。

没有大模型 Key 怎么办？用抽取式回答降级：只从原文挑与查询词项重合度最高的句子，原样输出并标来源，绝不自行组织不存在的结论。效果不如生成式自然，但守住"不编"这条底线。实测输出类似：

> 根据资料：混合检索的权重不是照抄默认值。[来源: 04_evaluation#000]

枯燥，但每句话都能查。

## 第三个问题：多轮追问把检索带偏

前两道防线解决单轮问题，多轮对话还有一个坑：用户爱用代词。

"为什么要使用混合检索？" → 回答之后用户追问"它为什么这么做？"。如果直接拿"它为什么这么做"去检索，向量里全是"它""为什么""怎么"这类没有区分度的词，召回质量断崖式下降。

查询改写的作用就是把追问改写成独立问题：

```python
def rewrite_query(query, history):
    if not history:
        return query, "无历史，直接使用原问题"
    llm = deepseek_chat([
        {"role": "system", "content": "把用户的追问改写成可独立检索的问题，只输出改写后的问题。"},
        {"role": "user", "content": "历史：" + " | ".join(history[-3:]) + "\n追问：" + query},
    ])
    if llm:
        return llm.strip(), "deepseek-rewrite"
    return " ".join(history[-2:] + [query]), "rule-based-rewrite-fallback"
```

有大模型时用提示词改写；没有就用规则降级，把最近两轮历史拼上来。规则降级虽然冗长，但至少把"混合检索"这个领域词带进了检索请求。

**关键细节**：域外判定必须作用在改写后的问题上。如果拿原始追问"它为什么这么做"去做词项覆盖判断，会因为没有任何领域词而误判为域外，把正常的追问拒掉。我自己就踩过这个坑——改完之后域内追问又正常了。

## 判断效果要看两个指标

幻觉抑制不能只看"回答听起来是否合理"。至少量化两项：

- **引用准确率**：回答标注的来源是否真的支持该结论
- **域外拒答率**：域外问题是否正确拒答，不能硬编

这两项都要有独立测试用例。我在评测集里放了域外题，并单独保存了拒答的运行证据（问题、判定结果、回答文本都记录成 JSON）。

## 还没解决的部分

抽取式降级回答会重复句子、偶尔截出半句碎片，可读性一般。真正的生成式回答要接大模型，接完之后引用准确率需要重新测——模型可能标注了来源但曲解原文。这些是当前版本的边界，写在 README 里，不装作已经解决。
